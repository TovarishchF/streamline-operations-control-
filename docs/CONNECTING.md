# CONNECTING.md — подключение внешних систем

Практическая инструкция для того, кто разворачивает систему: что подключено сейчас,
как включить, как проверить и что нужно, чтобы заработало остальное. Почему подключения
устроены так, а не иначе, — `INTEGRATIONS.md` и ADR-039.

---

## 1. Как это устроено

Заглушек нет. Подключение работает, если выполнены два условия:

1. для него написан адаптер `backend/integrations/<код>/live.py`;
2. его код перечислен в переменной `INTEGRATIONS_ENABLED` (через запятую).

Иначе система к внешней системе не обращается, а функции, которые на ней держатся,
недоступны. Ничего не выдумывается: что подключено — работает по-настоящему, чего
нет — того в системе нет.

```bash
INTEGRATIONS_ENABLED=FX,SMTP     # значение по умолчанию
```

Адаптеры сейчас есть у двух подключений: **FX** (курсы ЦБ РФ) и **SMTP** (исходящая
почта). Оба включены по умолчанию.

После правки `.env` контейнеры пересоздаются, иначе новые значения не прочитаются:

```bash
make up          # пересоздаёт контейнеры с изменённой конфигурацией
make restart     # только перезапуск api, worker, beat — после смены ветки
```

**Проверка.** Экран «Система → Интеграции» показывает только работающие подключения.
Кнопка «Проверить» делает настоящее обращение к внешней системе без побочных действий,
результат появляется сообщением и в журнале обменов (вкладка «Журнал обменов»).
Доступность в таблице — по последнему настоящему обмену: включённое, но недоступное
подключение выглядит недоступным.

Фоновые задачи (загрузка курсов, отправка почты) работают по расписанию Celery beat.
Расписание заводится один раз: `make setup-beat`.

## 2. Работают сейчас

### 2.1 FX — курсы валют ЦБ РФ

| | |
|---|---|
| Что даёт | Курсы USD и EUR к рублю на дату: маржа, документы, экран «Курсы валют» |
| От заказчика | Ничего. Источник открытый, ключ и регистрация не нужны |
| От сервера | Исходящий HTTPS до `www.cbr.ru:443` из контейнеров `api` и `worker` |
| Переменные | Только `FX` в `INTEGRATIONS_ENABLED` |
| Расписание | Ежедневно в 06:00 UTC (`fx.sync_rates`) |

Первый запуск — загрузить историю, иначе график курсов пуст, а документы прошлых дат
считать нечем:

```bash
docker compose exec api python manage.py sync_fx --days 60
```

Повторный запуск безопасен: курс за дату перезаписывается, а не дублируется.

Если сервер выходит в интернет через прокси, задайте контейнерам `api` и `worker`
переменную `HTTPS_PROXY` — адаптер её учитывает.

Без подключения новые курсы не появляются. Документы считаются по последнему
сохранённому курсу, экран курсов предупреждает, что курс устарел; курс старше двух
недель не подставляется вовсе.

### 2.2 SMTP — исходящая почта

| | |
|---|---|
| Что даёт | Заявки поставщикам, уведомления и документы клиентам по почте |
| В разработке | Mailpit в контейнере: письма отправляются по-настоящему и видны на `http://localhost:8025`, наружу не уходят. Настраивать ничего не нужно |
| От заказчика (бой) | Адрес сервера, порт, учётная запись, адрес отправителя на домене заказчика. На домене — записи SPF, DKIM и DMARC, иначе письма уйдут в спам |
| Расписание | Очередь исходящих отправляется каждые 30 секунд (`comms.send_outbox`) |

```bash
SMTP_HOST=smtp.example.ru
SMTP_PORT=587
SMTP_USE_TLS=true        # STARTTLS
SMTP_USER=soc@example.ru
SMTP_PASSWORD=...
SMTP_FROM=soc@example.ru
```

Поддерживается STARTTLS (обычно порт 587) и соединение без шифрования (25, только
во внутренней сети). Неявный TLS на порту 465 адаптер не поддерживает.

«Проверить» подключается к серверу, входит под учётной записью и запрашивает `NOOP` —
письмо при этом не отправляется. Статус сообщения «Отправлено» означает, что письмо
принял **наш** сервер исходящей почты; подтверждения доставки адресату SMTP не даёт.

Без подключения письма не уходят: сообщение сразу получает ошибку «подключение
не включено» и ждёт в исходящих, его можно отправить повторно после подключения.

## 3. Не подключены: адаптер ещё не написан

Для этих систем включение в `INTEGRATIONS_ENABLED` ничего не даст — нет адаптера.
Порядок у всех один: получить от заказчика перечисленное, написать адаптер
(оценка — в `INTEGRATIONS.md`), включить и проверить, как описано в § 1. Переменные
для учётных данных уже заведены в `.env.example`.

| Код | Что даст | Что нужно от заказчика | Что сейчас делает система |
|---|---|---|---|
| `MAILBOT` | Приём подтверждений и отказов поставщиков из почтового ящика | Выделенный ящик (например `ops@`), доступ по IMAP: `IMAP_HOST`, `IMAP_PORT`, `IMAP_USER`, `IMAP_PASSWORD`; согласие на автоматическую обработку | «Входящие» не пополняются. Подтверждения вносит диспетчер или поставщик в своём портале |
| `MSGR` | Уведомления диспетчерам в мессенджер MAX | Подтверждение, что у MAX есть Bot API для корпоративного контура (G-04), документация, токен бота, идентификаторы чатов. Либо решение об альтернативе — Telegram или почта | Канал недоступен: сообщение в мессенджер сразу получает ошибку |
| `LDAP` | Вход сотрудников по доменной учётной записи | Адрес контроллера домена, base DN, сервисная учётная запись только для чтения, сетевой доступ, соответствие групп AD ролям системы | Вход только локальными учётными записями. Для разработки адаптера в dev есть контейнер OpenLDAP |
| `ONEC` | Выгрузка счетов и заявок на оплату в 1С, приём сведений об оплатах | Версия и конфигурация 1С, адрес публикации OData, учётная запись, согласованный перечень реквизитов, ответственный за 1С | Обмена с 1С нет. Документы выгружаются файлами PDF и XLSX |
| `EDO` | Юридически значимая отправка закрывающих документов | Договор с оператором ЭДО (Диадок, СБИС, Такском), сертификат электронной подписи, доступ к API | Документы отправляются вне системы |
| `TRACK` | Фактическое время вылета и прилёта, автоматическая смена статуса рейса | Решение о бюджете: OpenSky (бесплатно, покрывает не все борта) или FlightAware AeroAPI | Статусы «В полёте» и «Прибыл» сменяются по плановому времени, фактическое время вносит диспетчер |
| `WX` | Погода METAR/TAF в аэропорту для решения о противообледенительной обработке | Ничего: источник NOAA открытый | Погоды в системе нет. Решение об обработке принимает командир ВС, система лишь напоминает о нём при заказе |
| `BI` | Подключение Power BI и Tableau | Перечень показателей, список подключающихся и их адреса (ADR-005 требует согласования) | Реплика и представления для BI не созданы. Отчёты выгружаются из раздела «Отчёты» |

## 4. Не подключаются: публичных подключений не существует

| Код | Почему | Что вместо подключения |
|---|---|---|
| `APT` | Это не подключение, а справочник | Аэропорты загружаются из `shared/reference/airports.csv` (OurAirports) командой `make seed-reference` и работают сразу |
| `SLOT` | Координаторы аэропортов работают сообщениями IATA SSIM по почте и через веб-кабинеты | Реестр слотов и подготовка сообщения SCR в системе (экран «Слоты») |
| `VENDOR_API` | У большинства FBO, топливных операторов и кейтеринга API нет | Портал поставщика в системе и почта |
| `IATA` | Участие в IATA SIS требует членства и сертификации (G-03) | Выгрузка в формате IS-XML файлом — запланирована (`INTEGRATIONS.md § 5.3`), пока не реализована |

## 5. Для разработчика: как добавить подключение

1. `backend/integrations/<код>/live.py` с классом `Provider`: методы по протоколу
   из `base.py` подключения и `check()` — обращение без побочных действий
   для кнопки «Проверить». Возвращают пару «результат, `Exchange`».
2. Назначение подключения — в `integrations.base.NAMES` (ru и en).
3. Доменный код вызывает только `get_provider("<КОД>")` и оборачивает вызов
   в `record_exchange()` — так обмен попадает в журнал (`CLAUDE.md § 3` п. 4).
   Перед вызовом, если функция необязательна, — `is_enabled("<КОД>")`.
4. Тесты не ходят в сеть: адаптер проверяется против записанного ответа системы
   (пример — `integrations/tests/fixtures/cbr-2026-09-11.xml`).
5. Код — в `INTEGRATIONS_ENABLED` в `.env.example` и в § 2 этого файла.
