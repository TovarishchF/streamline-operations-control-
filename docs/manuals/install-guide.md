# О поставке

В поставке три файла:

| Файл | Содержание |
|---|---|
| `soc-<версия>.tar.gz` | исходные тексты системы и всё необходимое для развёртывания |
| `Руководство пользователя.pdf` | работа в системе по ролям и экранам |
| `Инструкция по установке.pdf` | этот документ |

**Эта поставка — демонстрационная версия: при установке база наполняется
вымышленными данными встроенного генератора.** Как получить установку без
них — раздел «Установка без демонстрационных данных».

Система разворачивается на сервере с Docker одной командой. Все её части
(сервер приложения, база данных, фоновые задачи, веб-клиент, файловое
хранилище) собираются и запускаются в контейнерах на этом сервере.
Внешние облачные сервисы не нужны.

## Что представляет собой демонстрационная установка

Это рабочая система, а не макет: тот же сервер приложения, та же база
данных, те же расчёты и проверки, что и в рабочей установке. Отличие одно:
при первом запуске база наполняется **встроенным генератором данных**.

- **Компании, сотрудники, рейсы, договоры, цены, счета и суммы вымышлены.**
  Совпадения наименований с существующими организациями случайны. Цифры
  выручки и маржи на экранах — результат расчёта системы по данным
  генератора, а не показатели реального бизнеса.
- Настоящие только общедоступные справочные сведения: коды и координаты
  аэропортов, типы воздушных судов, коды валют. Курсы валют — официальные
  курсы Банка России.
- Данные строятся относительно даты установки: история за последние 30 дней
  и план на 14 дней вперёд. Система выглядит работающей «сегодня» в любой
  день установки.
- Записи генератора помечены в базе и удаляются одной командой. Частью набора
  считается и то, что человек завёл внутри него: рейс клиента из набора,
  заявки и документы по рейсам набора, платежи клиентов из набора. Остальное
  введённое людьми остаётся. Если запись человека ссылается на запись набора
  (например, цена, добавленная поставщику из набора), эта запись набора тоже
  остаётся, и очистка сообщает, какая и почему.

## Внешние подключения в этой установке

| Подключение | Состояние |
|---|---|
| Курсы валют Банка России | работает; серверу нужен доступ в интернет к `www.cbr.ru`. Если доступа нет, используются курсы Банка России, приложенные к поставке |
| Исходящая почта | работает; письма уходят на почтовый сервер внутри установки и наружу не выходят — адреса контрагентов вымышлены |
| 1С:Бухгалтерия, электронный документооборот, Active Directory, разбор входящей почты, корпоративный мессенджер, данные о движении ВС, погода в аэропортах | не подключены: подключения разрабатываются по мере получения доступов к системам заказчика. Система к ним не обращается и ничего за них не подставляет |

Мобильные приложения в поставку не входят. Веб-клиент работает в браузере
телефона и планшета (от 360 пикселей по ширине) и устанавливается на
главный экран как приложение.

# Требования к серверу

| Параметр | Значение |
|---|---|
| Операционная система | Linux x86-64: Ubuntu 22.04 или 24.04, Debian 12 и аналоги |
| Процессор | от 2 ядер, рекомендуется 4 |
| Память | от 4 ГБ, рекомендуется 8 ГБ |
| Диск | от 30 ГБ свободного места |
| Программы | Docker Engine 24 или новее с Docker Compose v2 |
| Сеть при установке | доступ в интернет: сборка загружает пакеты Python и Node.js и образы контейнеров |
| Входящий доступ | один порт для браузеров пользователей, по умолчанию 80 |

Установка проверена на x86-64 в Docker Desktop: те же контейнеры Linux, что и на
сервере. Работа на процессорах ARM не проверялась.

## Установка Docker

Если Docker на сервере уже есть, шаг пропускается. Проверка:

```bash
docker --version
docker compose version
```

Установка на Ubuntu и Debian официальным скриптом Docker:

```bash
curl -fsSL https://get.docker.com | sudo sh
```

Подробности и другие дистрибутивы — <https://docs.docker.com/engine/install/>.

# Установка

## Скопировать поставку на сервер

С компьютера, где лежит поставка:

```bash
scp soc-<версия>.tar.gz пользователь@сервер:~
```

На сервере:

```bash
tar -xzf soc-<версия>.tar.gz
cd soc
```

## Запустить установку

```bash
sudo sh deploy/sample/install.sh <адрес> [порт]
```

- **адрес** — IP-адрес или доменное имя, по которому систему будут открывать
  в браузере, например `203.0.113.10` или `soc.example.com`. Если его
  не указать, берётся первый IP-адрес сервера.
- **порт** — по умолчанию 80. Если порт 80 занят, укажите другой,
  например `8080`.

Пример:

```bash
sudo sh deploy/sample/install.sh 203.0.113.10
```

Скрипт:

1. проверяет, что Docker и Docker Compose установлены;
2. создаёт файл настроек `.env` со случайными паролями базы данных
   и хранилища и секретным ключом приложения;
3. собирает образы и запускает систему;
4. при первом запуске создаёт структуру базы, загружает справочники
   и курсы валют и строит набор демонстрационных данных.

Первая установка занимает **10–20 минут**, в зависимости от скорости
сервера и интернета. Повторные запуски — около минуты.

В конце скрипт выводит адрес системы и учётные записи:

```text
Готово: http://203.0.113.10
Пароль всех пользователей: soc-vhod-2026-parol
  volkova   — администратор
  karpov    — диспетчер
  gordeeva  — финансист
  sokolov   — руководитель
  lebedeva  — портал клиента
  zaharov   — портал поставщика
```

## Открыть систему

Откройте в браузере адрес из вывода скрипта. На экране входа показан список
учётных записей: щелчок по записи подставляет логин, остаётся ввести пароль.

| Логин | Роль | Что смотреть |
|---|---|---|
| `karpov` | диспетчер | суточный план, карточки рейсов, заказ услуг, поставщики |
| `gordeeva` | финансист | котировки, счета, платежи, сверка счетов поставщиков, маржа |
| `sokolov` | руководитель | дашборд руководителя, отчёты |
| `volkova` | администратор | всё перечисленное, пользователи, журнал аудита, подключения |
| `lebedeva` | клиент | портал клиента: свои рейсы, заявка на рейс, документы |
| `zaharov` | поставщик | портал поставщика: заявки, подтверждение, исполнение, оплаты |

Пароль всех учётных записей: **soc-vhod-2026-parol**.

Работа в системе описана в «Руководстве пользователя».

# Управление установкой

Команды выполняются на сервере из каталога `soc`.

| Действие | Команда |
|---|---|
| Состояние служб | `sudo docker compose -f docker-compose.sample.yml ps` |
| Остановить | `sudo docker compose -f docker-compose.sample.yml stop` |
| Запустить снова | `sudo docker compose -f docker-compose.sample.yml start` |
| Журналы сервера приложения | `sudo docker compose -f docker-compose.sample.yml logs -f api` |
| Пересоздать демонстрационные данные на сегодняшнюю дату | `sudo sh deploy/sample/reset-data.sh` |
| Удалить установку вместе с данными | `sudo docker compose -f docker-compose.sample.yml down -v` |

После перезагрузки сервера система запускается сама.

**Демонстрационные данные устаревают.** Набор построен на дату установки:
через неделю «вчерашние» рейсы окажутся недельной давности, а рейсы «на
завтра» — в прошлом. Перед показом пересоздайте данные командой
`reset-data.sh` — это занимает несколько минут. Введённое людьми вне набора
при этом сохраняется; записи набора, на которые оно ссылается, остаются, и команда
их перечисляет.

## Просмотр исходящей почты

Письма, которые отправляет система (заявки поставщикам, счета клиентам,
напоминания), видны в почтовом сервере установки. Он открыт только
на самом сервере, порт 8025. Чтобы посмотреть его со своего компьютера,
откройте туннель:

```bash
ssh -L 8025:localhost:8025 пользователь@сервер
```

и перейдите в браузере на `http://localhost:8025`.

## Смена адреса

Адрес, указанный при установке, записан в файл `.env` в двух строках:
`ALLOWED_HOSTS` (с какого адреса система принимает запросы)
и `S3_PUBLIC_ENDPOINT` (по какому адресу браузер скачивает файлы).
Если систему нужно открыть по другому адресу или порту, исправьте обе строки
и перезапустите службы:

```bash
sudo docker compose -f docker-compose.sample.yml up -d
```

# Установка без демонстрационных данных

Режим задаёт строка `SAMPLE_DATA` в файле `.env`. При `SAMPLE_DATA=false`
генератор данных и управление модельным временем отключены: команда
генератора отказывается работать, экрана «Генератор данных» нет, при запуске
служб набор не создаётся. Вместе с ней меняют ещё две строки:

| Строка | Демонстрация | Без демонстрационных данных |
|---|---|---|
| `SAMPLE_DATA` | `true` | `false` |
| `LOGIN_ACCOUNT_LIST` — список учётных записей на экране входа | `true` | `false` |
| `TWO_FACTOR_REQUIRED_ROLES` — кому обязателен второй фактор | пусто | `admin,finance` |

Первую учётную запись администратора в этой поставке создаёт генератор.
Поэтому установка без демонстрационных данных получается из
демонстрационной — до того, как в неё начали вводить рабочие данные:

1. Установите систему, как описано выше, и войдите под `volkova`.
2. На экране «Пользователи» (адрес `/admin/users`) заведите учётные записи
   администраторов и сотрудников с рабочими адресами почты. Учётные записи,
   заведённые людьми, при очистке остаются. Пароль при заведении
   не задаётся, а восстановления пароля по почте в системе пока нет:
   пароль каждой новой учётной записи задаётся на сервере командой
   (логин — адрес почты):

   ```bash
   sudo docker compose -f docker-compose.sample.yml exec api python manage.py changepassword <адрес почты>
   ```
3. Удалите демонстрационные данные:

   ```bash
   sudo docker compose -f docker-compose.sample.yml exec -T api python manage.py seed_sample --purge
   ```

   Удаляются записи генератора и его учётные записи, в том числе `volkova`.
   Справочники (аэропорты, типы ВС, услуги, ставки НДС, шаблоны писем) и курсы
   валют остаются: они не вымышлены. Журнал аудита не очищается — он только
   пополняется; действия генератора в нём подписаны «Система (генератор
   данных)». Если в конце вывода перечислены оставленные записи набора, на них
   ссылаются заведённые людьми записи; уберите эти ссылки и повторите команду —
   после шага 4 она уже недоступна.
4. В `.env` задайте значения из правого столбца таблицы и перезапустите
   службы:

   ```bash
   sudo docker compose -f docker-compose.sample.yml up -d
   ```

5. Войдите под учётной записью из шага 2. Администратору и финансисту
   при первом входе будет предложено привязать приложение-аутентификатор.

Развернуть установку сразу без демонстрационных данных эта поставка
не позволяет: в пустой базе нет учётной записи, под которой можно войти.
Порядок развёртывания рабочей установки (резервное копирование, HTTPS,
подключения к системам заказчика) описывается в руководстве администратора,
которое готовится к сдаче системы.

# Безопасность

Демонстрационная установка предназначена для просмотра и проверки системы.

- Пароль учётных записей демонстрации общеизвестен — он напечатан в этой
  инструкции. Не открывайте установку в интернет надолго; ограничьте доступ
  к порту сетевым экраном по адресам тех, кто смотрит систему.
- Установка работает по HTTP, без шифрования. Для работы через интернет
  поставьте перед ней обратный прокси с сертификатом (nginx, Caddy,
  балансировщик облака) и задайте в `.env` значение `HTTPS_ONLY=true`.
- Пароли базы данных и хранилища случайные и хранятся в `.env` с правами
  только для владельца. Наружу открыт только порт веб-клиента: база данных,
  хранилище и очереди задач доступны лишь внутри установки.

# Неполадки

| Признак | Что делать |
|---|---|
| Скрипт сообщает, что не найден Docker | установите Docker (раздел «Установка Docker») |
| Сборка останавливается с ошибкой загрузки | на сервере нет доступа в интернет или он ограничен прокси; повторите установку, когда доступ появится — скрипт продолжит с места остановки |
| `port is already allocated` | порт занят другой программой; в `.env` замените порт в строках `HTTP_PORT` и `S3_PUBLIC_ENDPOINT` и выполните `sudo docker compose -f docker-compose.sample.yml up -d` |
| В журнале установки «ЦБ РФ недоступен» | сервер не видит `www.cbr.ru`; система работает на курсах из поставки. Свежие курсы загрузятся сами, когда доступ появится |
| Страница входа не открывается | проверьте, что порт открыт в сетевом экране, и состояние служб командой `ps` — все службы, кроме `init`, должны быть в состоянии `running` |
| Вход проходит, но файлы (акты, выгрузки) не скачиваются | систему открывают не по тому адресу, что указан при установке; см. «Смена адреса» |
| Служба `init` завершилась с ошибкой | посмотрите её журнал: `sudo docker compose -f docker-compose.sample.yml logs init` |
