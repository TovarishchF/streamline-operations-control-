# SOC — Streamline Operations Control

Единая диспетчерская платформа управления полётами и логистическими услугами.
Разработана по техническому заданию ООО «Стримлайн Група» (`docs/ТЗ_SOC.docx`).

---

## Состав

| Компонент | Технологии |
|---|---|
| Сервер | Python 3.12, Django 5.1, DRF, PostgreSQL 16, Redis, Celery |
| Веб-клиент | TypeScript, React 18, Vite, Ant Design 5 |
| Мобильные приложения | React Native, Expo (iOS / Android) |
| Хранилище файлов | S3-совместимое (MinIO на on-premise) |
| Развёртывание | Docker Compose, nginx, pgBackRest |

Архитектура описана в `docs/BACKEND.md` (серверная часть) и `docs/INFRA.md` (развёртывание).
API описан в `openapi.yaml`, публикуется системой по адресу `/api/docs`.

## Режимы работы

### Режим генератора данных

`SAMPLE_DATA=true`.

Это полноценная система: тот же сервер, та же база, те же расчёты, то же API и те же
внешние подключения. Отличаются только данные: вместо данных заказчика в базе
сгенерированный набор. Заглушек внешних систем нет (ADR-039).

Как устроен набор:
- у всех записей генератора `is_generated = true` и `data_source = synthetic`;
- в интерфейсе и выгрузках режим не обозначается;
- на экране `/admin/integrations` видны только работающие подключения.

### Рабочий режим

`SAMPLE_DATA=false`, внешние системы подключаются по мере получения доступов
(`docs/CONNECTING.md`).
Генератор данных недоступен.

## Состояние внешних подключений

Полный реестр, включая то, что требуется получить от заказчика по каждому пункту, —
`docs/INTEGRATIONS.md`. Текущее состояние заполняется по факту:

| Код | Назначение | Состояние | Что нужно |
|---|---|---|---|
| `FX` | курсы валют | | источник ЦБ РФ, доступен без ключей |
| `WX` | METAR/TAF | | открытый источник, доступен без ключей |
| `TRACK` | данные о движении ВС | | решение по бюджету на источник |
| `APT` | справочник аэропортов | | открытый набор данных, загружается локально |
| `SMTP` | исходящая почта | | сервер, учётные данные, настройка SPF/DKIM/DMARC |
| `MSGR` | мессенджер MAX | | документация Bot API, токен |
| `MAILBOT` | разбор входящей почты | | выделенный ящик, доступ по IMAP |
| `LDAP` | аутентификация через AD | | адрес КД, base DN, сервисная запись |
| `ONEC` | 1С:Бухгалтерия | | адрес публикации OData, учётная запись |
| `EDO` | электронный документооборот | | договор с оператором, сертификат ЭП |
| `BI` | Power BI / Tableau | | реплика только для чтения, перечень показателей |
| `SLOT` | слот-координация | | публичного подключения не существует |
| `VENDOR_API` | системы поставщиков | | отраслевого стандарта не существует |
| `IATA` | IATA SIS / ISS | | членство и сертификация |

Неподключённая система ничем не подменяется: функции, которые на ней держатся,
недоступны, а каждый вызов подключённой пишется в журнал обменов.

## Что не реализовано

- Поддержка MSSQL (п. 4.1 ТЗ). Реализована только PostgreSQL; обоснование —
  `docs/DECISIONS.md`, требует согласования с заказчиком.
- Модули экипажа и его допусков, технического состояния ВС за пределами признака AOG,
  расчёта маршрута с учётом ветра и эшелонов — в ТЗ отсутствуют, зафиксированы
  в `docs/GAPS.md`.
- Сертификация в IATA SIS/ISS.
- Юридическая экспертиза налоговых расчётов: справочник ставок реализован, соответствие
  требованиям законодательства подтверждается бухгалтером заказчика.
- Подключения, отмеченные выше как несуществующие публично, закрываются ручным контуром
  (почта и портал поставщика).

Полная таблица соответствия пунктам ТЗ — `docs/TRACEABILITY.md`.
Открытые вопросы к заказчику — `docs/GAPS.md`.

## Запуск

```bash
cp .env.example .env        # заполнить
make up
make migrate
make seed-reference
make seed-sample            # только при SAMPLE_DATA=true
```

Веб-клиент — `http://localhost:5173`, API — `http://localhost:8000/api/v1`,
документация API — `/api/docs`, почта разработки (Mailpit) — `http://localhost:8025`.

Развёртывание боевого контура — `docs/INFRA.md § 8`.
