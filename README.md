# SOC — Streamline Operations Control

Единая диспетчерская платформа управления полётами и логистическими услугами.
Разработана по техническому заданию ООО «Стримлайн Група» (`docs/ТЗ_SOC.docx`).

> **Состояние на 28.10.2026: закрыты вехи M0–M10 из `docs/TASKS.md`, M11 (установка
> для показа) сделана, кроме размещения на сервере по ссылке для заказчика.** M2 ждёт
> утверждения интерфейсов заказчиком, у M1, M7, M9 и M11 есть остатки — они перечислены
> ниже. Сервер и веб-клиент работают на настоящем API: рейсы, услуги, контрагенты,
> биллинг, коммуникации, порталы, отчётность. Впереди — мобильные приложения (M12),
> внешние подключения (M13, M14), испытания под нагрузкой и восстановление (M15).
> Что именно работает, а что нет, честно перечислено ниже.

## Режимы работы

### Рабочий режим

`SAMPLE_DATA=false`. Внешние системы подключаются по мере получения доступов
от заказчика (`docs/CONNECTING.md`). Генератор данных и управление модельным временем
недоступны.

### Режим генератора данных

`SAMPLE_DATA=true`. Это не макет: тот же сервер, та же база, те же расчёты и то же API.
В базе — набор генератора; внешние подключения те же, что в рабочем режиме.

Как устроен набор:
- у всех записей генератора `is_generated = true` и `data_source = synthetic`;
  `make sample-reset` удаляет только их и собирает набор заново;
- записи аудита от генератора подписаны автором `Система (генератор данных)`
  и не выдаются за действия людей;
- в интерфейсе и выгрузках режим не обозначается.

**Заглушек внешних систем нет** (ADR-039). Подключение работает по-настоящему либо
выключено, и тогда система к нему не обращается и ничего за него не выдумывает.
Работающие подключения видны на `/admin/integrations`.

## Состояние внешних подключений

Полный реестр, включая то, что требуется получить от заказчика по каждому пункту, —
`docs/INTEGRATIONS.md`. Письмо с запросом доступов —
`docs/letters/2026-09-13-запрос-доступов-и-решений.md`.

Как включить и проверить каждое подключение — `docs/CONNECTING.md`.

| Код | Назначение | Состояние | Что нужно |
|---|---|---|---|
| `FX` | курсы валют ЦБ РФ | **работает**, включён по умолчанию | исходящий HTTPS до `www.cbr.ru` |
| `SMTP` | исходящая почта | **работает**, включён по умолчанию; в dev — Mailpit | сервер, учётные данные, SPF/DKIM/DMARC |
| `APT` | справочник аэропортов | **работает**: не подключение, а справочник, загружается один раз (`INTEGRATIONS § 2.4`) | ничего |
| `WX` | METAR/TAF | адаптер не написан | ничего: источник NOAA открыт |
| `TRACK` | данные о движении ВС | адаптер не написан | решение по бюджету на источник |
| `MAILBOT` | разбор входящей почты | адаптер не написан; разбор писем и экран «Входящие» готовы | выделенный ящик, доступ по IMAP |
| `MSGR` | мессенджер MAX | адаптер не написан | документация Bot API, токен — **не подтверждено** |
| `LDAP` | аутентификация через AD | адаптер не написан | адрес КД, base DN, сервисная запись |
| `ONEC` | 1С:Бухгалтерия | адаптер не написан | адрес публикации OData, учётная запись, перечень реквизитов |
| `EDO` | электронный документооборот | адаптер не написан | договор с оператором, сертификат ЭП |
| `BI` | Power BI / Tableau | не создано | реплика только для чтения, перечень показателей |
| `SLOT` | слот-координация | **публичного подключения не существует**; реестр слотов и сообщения SCR в системе | — |
| `VENDOR_API` | системы поставщиков | **отраслевого стандарта не существует**; портал поставщика и почта | — |
| `IATA` | IATA SIS / IS-XML | участие требует членства и сертификации; выгрузка IS-XML файлом запланирована, не реализована | уточнение по «BDG» |

## Что реализовано на сегодня

**M0 — требования и контракт**
- `openapi.yaml`: 93 пути, 134 схемы, валиден по OpenAPI 3.1 (проверяется автоматически);
- `docs/GAPS.md`: 54 записи — противоречия ТЗ, пробелы модели, вопросы заказчику;
- `docs/DECISIONS.md`: 34 архитектурных решения с обоснованием и ценой отката;
- `docs/TRACEABILITY.md`: 176 строк требований по всем разделам ТЗ, строк без статуса нет;
- письмо заказчику с перечнем блокирующих пунктов.

**M1 — каркас**
- структура монорепозитория, `Makefile`, `docker-compose.yml` с профилями dev/sample/prod;
- Django-проект с разделением настроек, `core.money` и `core.clock`;
- `GET /api/v1/health` и `GET /api/v1/clock`;
- веб-клиент: Vite + React + TS strict + Ant Design + i18next (ru/en) + TanStack Query;
- генерация `shared/api-types.ts` из контракта;
- определения автоматов в `shared/state-machines/`, общие для сервера и клиента;
- CI: линтеры, типы, тесты, сверка схемы сервера с контрактом.

**M2 — кликабельные макеты**
- 46 экранов по `SPEC.md § 3`, снимки в `artifacts/screenshots/m2/`;
- ожидает утверждения заказчиком.

**M3 — ядро сервера**
- справочники из открытых источников: 1351 аэропорт (OurAirports, OpenFlights),
  46 типов воздушных судов, 24 услуги по категориям ТЗ 3.2.1, 7 ставок НДС
  (базовая — 22 % с 01.01.2026, Федеральный закон № 425-ФЗ);
  часовые зоны 82 аэропортов СНГ выверены вручную, остальные проверяются
  на согласованность с долготой;
- доступ: JWT, TOTP-2FA с одноразовыми резервными кодами, блокировка после пяти
  неудачных попыток, политика паролей, карта «роль → право» едина с клиентом;
- мультиарендность: фильтрация выборки для порталов, чужая запись даёт 404
  и не попадает ни в список, ни в счётчик;
- журнал действий: неизменяем на уровне базы, изменение и удаление отклоняет триггер;
- эндпоинты `/auth/*`, `/airports`, `/aircraft-types`, `/vat-rates`,
  `/catalog/services`, `/fleet`, `/audit`, `/users` — 21 операция из 115 по контракту;
- веб-клиент: настоящий вход вместо переключателя ролей, экраны справочников
  работают на сервере;
- генератор данных: вымышленные контрагенты, настоящие справочные коды, пометка
  `is_generated` и происхождение `synthetic` на каждой записи.

**M4 — рейсы**
- автомат рейса на `django-fsm-2` по общему с клиентом определению
  `shared/state-machines/flight.json`; недоступный переход называет невыполненные условия;
- расстояние, блок-тайм и плановое топливо; детектор конфликтов: пересечения,
  разворот, борт в AOG или на ТО, истёкший допуск;
- серии рейсов из шаблона с переводом местного времени в UTC; реестр слотов;
  история изменений рейса из журнала действий.

**M5 — услуги и заявки**
- цены поставщиков с периодами и надбавками; заявка со снимком закупочной цены;

**M6 — контрагенты и контракты**

## Что не реализовано

Впереди по вехам `docs/TASKS.md`:

- **мобильные приложения** — M12;
- **внешние подключения в режиме `live`**, кроме `FX` и `SMTP` — M13, M14;
- **нагрузочные испытания k6 и испытание восстановления** — M15.

Остатки закрытых вех и известные ограничения:

- **неизменяемость выставленного документа в базе** (M7): изменение запрещают
  сервис и отсутствие эндпоинта, ограничение базы требует номер и дату, но прямой
  `UPDATE` сумм база пока не отклоняет — нужен триггер;
- **замер самого тяжёлого отчёта** на полном наборе генератора (M9): набор есть,
  замер не выполнен;
- **статус «оплачена» у заявок на оплату поставщикам** появится только с подключением
  1С (`ONEC`): без него прошедшие сроки копятся как просрочка;
- **настройка пользователя `timezoneMode`** хранится, но экраны по ней не
  переключаются: время везде в UTC с подписью зоны, в карточке рейса — и местное
  время аэропорта;
- **письма клиенту о вылете, завершении рейса и AOG** не отправляются, пока
  заказчик не даст их тексты (`GAPS.md` G-56);
- **`GET /crew`** из контракта сервером не реализован — единственная такая операция
  из 137;
- **реестры поставщиков, клиентов и договоров** загружаются одним запросом до 200
  записей: при большем объёме нужна постраничная выдача сервера;
- **утверждение интерфейсов заказчиком** (M2);
- **пароль новой учётной записи**: пользователь, заведённый на экране «Пользователи»,
  не может войти, пока пароль не задан на сервере командой `changepassword`;
  восстановления пароля по почте и смены своего пароля в интерфейсе нет, а подсказка
  формы заведения обещает письмо, которое не отправляется;
- **установка сразу без демонстрационных данных**: в пустой базе нет учётной записи
  для входа; рабочая установка получается из демонстрационной очисткой набора
  («Инструкция по установке»);
- **выгрузка котировки** в PDF и XLSX — выгружается только счёт;
- **сборы и комиссии** в котировках и счетах нигде не задаются — их итог всегда 0;
- **предоплата и постоплата** клиента хранятся, но на расчёты не влияют: срок оплаты
  счёта считается по дням отсрочки; наценки фиксированной суммой нет;
- **заблаговременные оповещения о сроках**: напоминаний поставщикам о сроках исполнения
  и уведомлений о приближении сроков подтверждения и оплаты нет — оповещения приходят
  об истечении договора и уже о просрочке;
- **допуски экипажа** (`CrewQualification`, ADR-027) не заведены; для ПДн экипажа нет
  ограничения доступа, журнала обращений и обезличивания по сроку (ADR-028);
- **адрес поставщика** не хранится — только страна;
- **испытания**: нет теста на протечку данных для `GET /quotes` под ролью клиента,
  контрактный прогон `schemathesis` не настроен; без испытаний работают смена маршрута
  рейса, условия «разрешение получено» и «слот подтверждён» перехода в «Готов к вылету»,
  переход в AOG, автопереход по времени, запись выставления счёта в журнал и заявка
  клиента по своему шаблону. Перечень — строки `в работе` в `docs/TRACEABILITY.md`.
  Сквозной сценарий нестабилен на шаге «Сформировать счёт»: в одном из двух прогонов
  28.10.2026 нажатие «Создать» в диалоге не отправило запрос, причина не найдена.

Не реализуется по принятым решениям:

- **Поддержка MSSQL** (ТЗ 4.1). Только PostgreSQL 16; обоснование — ADR-001,
  требует согласования с заказчиком.
- **Кластеризация СУБД** (ТЗ 4.1) заменена репликой с ручным переключением (ADR-001).
- **Сертификация в IATA SIS/ISS** — реализуется только выгрузка в формате IS-XML (ADR-032).
- **Юридическая экспертиза налоговых расчётов**: справочник ставок реализуется,
  соответствие требованиям законодательства подтверждается бухгалтером заказчика.
- **Учёт рабочего времени экипажа (FTL)** — требует регламента заказчика, вне объёма (ADR-027).
- **Поимённый учёт пассажиров** — хранится только количество (ADR-028).
- **Технический учёт рабочих мест по лицензиям** (ТЗ 6) — вне объёма, G-08.

Полная таблица соответствия пунктам ТЗ — `docs/TRACEABILITY.md`.
Открытые вопросы к заказчику — `docs/GAPS.md`.

## Запуск

### В контейнерах

```bash
cp .env.example .env        # заполнить
make up
make migrate
make seed-reference
make seed-sample            # только при SAMPLE_DATA=true
```

Веб-клиент — `http://localhost:5173`, API — `http://localhost:8000/api/v1`,
документация API — `/api/docs`, почта разработки (Mailpit) — `http://localhost:8025`.

### Установка для показа на сервере

```bash
sh deploy/sample/install.sh <адрес> [порт]   # .env со случайными паролями, сборка, данные
sh deploy/sample/reset-data.sh               # набор генератора на сегодняшнюю дату
```

Поставка для передачи — `make manuals && make release` → `release/SOC-<дата>-<коммит>/`.
Порядок установки, в том числе переход к установке без демонстрационных данных
(`SAMPLE_DATA=false`), — `docs/manuals/install-guide.md`.

### Локально, без Docker

```bash
make install                # создаёт backend/.venv на Python 3.12
cd web && npm install
make check                  # линтеры, типы, тесты
```

Для сервера нужен Python 3.12 и запущенные PostgreSQL и Redis.
Развёртывание боевого контура — `docs/INFRA.md § 8`.
