# SOC — Streamline Operations Control

Единая диспетчерская платформа управления полётами и логистическими услугами.
Разработана по техническому заданию ООО «Стримлайн Група» (`docs/ТЗ_SOC.docx`).

> **Состояние на 13.09.2026: закрыты вехи M0 и M1 из `docs/TASKS.md`.**
> Согласован контракт API, зафиксированы решения и пробелы, поднят каркас
> монорепозитория с ядром сервера и веб-клиента. Доменные модули (рейсы, услуги,
> контрагенты, биллинг, коммуникации, отчётность) — впереди, вехи M3–M10.
> Что именно уже работает, а что нет, честно перечислено ниже.

## Режимы работы

### Боевой режим

`DEMO_DATA=false`. Подключения переводятся в `live` по мере получения доступов
от заказчика. Маркировка демонстрационного режима не выводится, команда генерации
демонстрационных данных недоступна.

### Демонстрационный стенд

`DEMO_DATA=true`. Это не макет: тот же сервер, та же база, те же расчёты и то же API.
Отличаются только источники данных — в базе сгенерированный набор, а часть внешних
подключений работает заглушками.

Признаки демонстрационного режима:
- маркер `ДЕМО-СТЕНД` в интерфейсе;
- отметка `DEMO` на всех выгружаемых документах и отчётах;
- у всех сгенерированных записей `data_source = synthetic`;
- записи аудита от генератора помечены автором `System (демо-генератор)`
  и не выдаются за действия людей.

**Режим подключения и демонстрационность данных — разные вещи** (ADR-008). Подключение
в режиме `stub` не делает боевой счёт демонстрационным: часть внешних систем
(ЭДО, слот-координация, системы поставщиков) останется в режиме заглушки постоянно,
и водяной знак `DEMO` на настоящих документах клиентов был бы не честностью,
а испорченным документом. Фактический режим каждого подключения виден
на `/admin/integrations`.

## Состояние внешних подключений

Полный реестр, включая то, что требуется получить от заказчика по каждому пункту, —
`docs/INTEGRATIONS.md`. Письмо с запросом доступов —
`docs/letters/2026-09-13-запрос-доступов-и-решений.md`.

| Код | Назначение | Режим | Что нужно для `live` |
|---|---|---|---|
| `FX` | курсы валют | `stub` | ничего: источник ЦБ РФ открыт |
| `WX` | METAR/TAF | `stub` | ничего: источник NOAA открыт |
| `APT` | справочник аэропортов | — | адаптер не нужен: справочник загружается один раз и хранится в базе (`INTEGRATIONS § 2.4`). Загружен |
| `TRACK` | данные о движении ВС | `stub` | решение по бюджету на источник |
| `SMTP` | исходящая почта | `stub` | сервер, учётные данные, SPF/DKIM/DMARC |
| `MAILBOT` | разбор входящей почты | `stub` | выделенный ящик, доступ по IMAP |
| `MSGR` | мессенджер MAX | `stub` | документация Bot API, токен — **не подтверждено** |
| `LDAP` | аутентификация через AD | `stub` | адрес КД, base DN, сервисная запись |
| `ONEC` | 1С:Бухгалтерия | `stub` | адрес публикации OData, учётная запись, перечень реквизитов |
| `EDO` | электронный документооборот | `stub` | договор с оператором, сертификат ЭП |
| `BI` | Power BI / Tableau | `stub` | реплика только для чтения, перечень показателей |
| `SLOT` | слот-координация | `stub` | **публичного подключения не существует** |
| `VENDOR_API` | системы поставщиков | `stub` | **отраслевого стандарта не существует** |
| `IATA` | IATA SIS / IS-XML | `stub` | членство и сертификация |

Все адаптеры находятся на вехе M13; сейчас реализован только каркас конфигурации режимов.
Исключение — справочник аэропортов: по `INTEGRATIONS § 2.4` он загружается один раз,
заглушка ему не нужна, и он уже наполнен настоящими открытыми данными.

## Что реализовано на сегодня

**M0 — требования и контракт**
- `openapi.yaml`: 93 пути, 134 схемы, валиден по OpenAPI 3.1 (проверяется автоматически);
- `docs/GAPS.md`: 54 записи — противоречия ТЗ, пробелы модели, вопросы заказчику;
- `docs/DECISIONS.md`: 34 архитектурных решения с обоснованием и ценой отката;
- `docs/TRACEABILITY.md`: 176 строк требований по всем разделам ТЗ, строк без статуса нет;
- письмо заказчику с перечнем блокирующих пунктов.

**M1 — каркас**
- структура монорепозитория, `Makefile`, `docker-compose.yml` с профилями dev/demo/prod;
- Django-проект с разделением настроек, `core.money` и `core.clock`;
- `GET /api/v1/health` и `GET /api/v1/clock`;
- веб-клиент: Vite + React + TS strict + Ant Design + i18next (ru/en) + TanStack Query;
- генерация `shared/api-types.ts` из контракта;
- определения автоматов в `shared/state-machines/`, общие для сервера и клиента;
- CI: линтеры, типы, тесты, сверка схемы сервера с контрактом.

**M2 — кликабельные макеты**
- 46 экранов по `SPEC.md § 3`, снимки в `artifacts/screenshots/m2/`;
- ожидает утверждения заказчиком.

**M3 — ядро сервера**
- справочники из открытых источников: 1351 аэропорт (OurAirports, OpenFlights),
  46 типов воздушных судов, 24 услуги по категориям ТЗ 3.2.1, 7 ставок НДС;
  часовые зоны 82 аэропортов СНГ выверены вручную, остальные проверяются
  на согласованность с долготой;
- доступ: JWT, TOTP-2FA с одноразовыми резервными кодами, блокировка после пяти
  неудачных попыток, политика паролей, карта «роль → право» едина с клиентом;
- мультиарендность: фильтрация выборки для порталов, чужая запись даёт 404
  и не попадает ни в список, ни в счётчик;
- журнал действий: неизменяем на уровне базы, изменение и удаление отклоняет триггер;
- эндпоинты `/auth/*`, `/airports`, `/aircraft-types`, `/vat-rates`,
  `/catalog/services`, `/fleet`, `/audit`, `/users` — 21 операция из 115 по контракту;
- веб-клиент: настоящий вход вместо переключателя ролей, экраны справочников
  работают на сервере;
- генератор демонстрационных данных: вымышленные контрагенты, настоящие справочные
  коды, пометка `is_demo` и происхождение `synthetic` на каждой записи.

## Что не реализовано

Доменная функциональность впереди. По вехам `docs/TASKS.md`:

- **рейсы, суточный план, Gantt** — M4, M10. Экраны расписания, рейсов, биллинга,
  коммуникаций и порталов пока работают на наборе для макетов, а не на сервере;
- **заявки на услуги и SLA** — M5;
- **контрагенты, контракты, рейтинг, подбор поставщика** — M6;
- **биллинг: тарифы, котировки, счета, сверка, маржа** — M7;
- **коммуникации и порталы** — M8;
- **отчётность и дашборды** — M9;
- **мобильные приложения** — M12;
- **внешние подключения в режиме `live`** — M13, M14.

Не реализуется по принятым решениям:

- **Поддержка MSSQL** (ТЗ 4.1). Только PostgreSQL 16; обоснование — ADR-001,
  требует согласования с заказчиком.
- **Кластеризация СУБД** (ТЗ 4.1) заменена репликой с ручным переключением (ADR-001).
- **Сертификация в IATA SIS/ISS** — реализуется только выгрузка в формате IS-XML (ADR-032).
- **Юридическая экспертиза налоговых расчётов**: справочник ставок реализуется,
  соответствие требованиям законодательства подтверждается бухгалтером заказчика.
- **Учёт рабочего времени экипажа (FTL)** — требует регламента заказчика, вне объёма (ADR-027).
- **Поимённый учёт пассажиров** — хранится только количество (ADR-028).
- **Технический учёт рабочих мест по лицензиям** (ТЗ 6) — вне объёма, G-08.

Полная таблица соответствия пунктам ТЗ — `docs/TRACEABILITY.md`.
Открытые вопросы к заказчику — `docs/GAPS.md`.

## Запуск

### В контейнерах

```bash
cp .env.example .env        # заполнить
make up
make migrate
make seed-reference
make seed-demo              # только при DEMO_DATA=true
```

Веб-клиент — `http://localhost:5173`, API — `http://localhost:8000/api/v1`,
документация API — `/api/docs`, почтовая заглушка — `http://localhost:8025`.

### Локально, без Docker

```bash
make install                # создаёт backend/.venv на Python 3.12
cd web && npm install
make check                  # линтеры, типы, тесты
```

Для сервера нужен Python 3.12 и запущенные PostgreSQL и Redis.
Развёртывание боевого контура — `docs/INFRA.md § 8`.
